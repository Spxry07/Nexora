# Skinned Model NPCs (round 8) — posable skinned limbs, no resource pack

Technique (same idea FlexibleNPC uses, our own packet-based implementation): an NPC body built from player-head ItemDisplays. Each body part gets its own Mojang-signed head texture generated through the MineSkin API from a slice of the NPC's skin, so every cube shows the right skin pixels. Limbs rotate freely via Display transformations; the client interpolates.

## Parts (`net.spxry.nexora.npc.SkinParts.Part`, lead writes the enum)
`HEAD, TORSO_UPPER, TORSO_LOWER, RIGHT_ARM_UPPER, RIGHT_ARM_LOWER, LEFT_ARM_UPPER, LEFT_ARM_LOWER, RIGHT_LEG_UPPER, RIGHT_LEG_LOWER, LEFT_LEG_UPPER, LEFT_LEG_LOWER`.
Dimensions in skin pixels (w × h × d): HEAD 8×8×8 (uses the ORIGINAL skin texture, no generation); torso halves 8×6×4; arm halves 4×6×4 (3×6×4 for slim/Alex skins); leg halves 4×6×4.

## SkinParts service (`plugin.skinParts()`)
- `CompletableFuture<Optional<Map<Part, ProfileProperty>>> request(String skinId)` · `Optional<Map<Part, ProfileProperty>> cached(String skinId)` · `Status status(String skinId)` (`enum Status {READY, GENERATING, FAILED, NO_KEY, NO_SKIN}`) · `void shutdown()`.
- skinId = `Npc.skinId()` (texture hash or player name). Source PNG: `http://textures.minecraft.net/texture/{hash}` or `https://mc-heads.net/skin/{name}` (config `model.skin-url.hash` / `model.skin-url.name`), validated id, ≤64 KB, 64×64 (64×32 legacy → no overlays). Slim detection: pixel (54,20) alpha == 0 in 64×64 skins → slim.
- For each non-HEAD part build a fresh 64×64 RGBA skin whose HEAD region (base layer x0-31 y0-15, hat layer x32-63 y0-15) contains that part's faces: map each part face (front/back/left/right/top/bottom from the standard 64×64 layout, upper half = top 6 rows of the limb's side faces, lower half = bottom 6 rows; top face of upper half = limb top, bottom face of lower half = limb bottom, the cut faces use the adjacent row) onto the corresponding 8×8 head face with nearest-neighbour resize; overlay layer (jacket/sleeve/pants regions) → hat region. Everything else transparent.
- Upload via MineSkin v2: `POST https://api.mineskin.org/v2/queue` JSON `{"url":"data:image/png;base64,...","visibility":"unlisted","variant":"classic","name":"nexora-<part>"}`, headers `Authorization: Bearer <model.mineskin.api-key>`, `User-Agent: <model.mineskin.user-agent>`. Response 200 → done (`skin.texture.data.value` + `.signature`); 202 → poll `GET /v2/queue/{job.id}` every `model.mineskin.poll-ms` until `job.status` completed/failed; honour 429 `Retry-After` / `rateLimit.next.relative`. One part at a time (sequential queue on a single `nexora-mineskin` thread), max `model.mineskin.max-concurrent-skins` skins in flight.
- Cache: `plugins/Nexora/skin-parts.yml` keyed by skinId → part → {value, signature}; loaded at startup on that thread, saved after each completed skin. No key → status NO_KEY and nothing is requested.

## Model NPC (`entity-type: MODEL`, label "Skinned Model (posable)")
- Template entities: 11 `ItemDisplay` (PLAYER_HEAD with `DataComponentTypes.PROFILE` = ResolvableProfile with the part's `textures` ProfileProperty; HEAD uses the NPC's own profile), item display transform from `model.item-transform` (default NONE), interpolation & teleport duration = animation interval; one `Interaction` entity (width `model.hitbox-width` 0.6, height 1.8 × scale) for clicks (its id must be in entityIds so InteractListener resolves it); optional main/off-hand `ItemDisplay`s for HAND/OFF_HAND equipment, attached to the lower-arm end and rotated with the arm.
- While parts are not READY: render as a MANNEQUIN (current behaviour) and `request()` them; when they arrive → `plugin.objects().mutate(this, n -> {})` once to rebuild as a model.
- Geometry (pixels, 1 px = scale/16 block, origin at feet, model faces +Z at yaw 0): joints — neck (0,24,0); body pivot (0,12,0); shoulders (±6,22,0) (right arm at x -6 i.e. the model's right; slim arms 3 px wide shift centre by 0.5 px); hips (±2,12,0). Part centres relative to their joint: head (0,4,0); torso upper (0,9,0) lower (0,3,0) relative to body pivot; arm upper (0,-1,0) lower (0,-7,0); leg upper (0,-3,0) lower (0,-9,0). Head and arms are children of the body (their joints rotate with the body rotation). Whole model rotated by NPC yaw.
- Head cube geometry at display scale 1 (configurable, tune in-game): cube edge `model.cube-size` (0.5 block = 8 px) with its centre at `model.cube-offset` (0,-0.25,0) in display-local space. Part scale vector = (w,h,d)/8 × npc scale. Transformation per part: leftRotation = Ryaw·Rparent·Rlimb, translation = Ryaw·(world joint offset) + Rtotal·(centreRel − S·cubeOffset) — use JOML.
- Limb angles in degrees, armor-stand style: x = pitch (positive swings the limb FORWARD), y = yaw/twist, z = roll (positive swings the arm OUTWARD). Static pose props `pose-head`, `pose-body`, `pose-right-arm`, `pose-left-arm`, `pose-right-leg`, `pose-left-leg` (text "x,y,z", default "0,0,0") + keyframe limb tokens `head= body= larm= rarm= lleg= rleg=` added ON TOP of the static pose. Gesture tokens (pose/use/swing) ignored for models; `item=`/`offitem=` change the hand item displays.
- Walking along a path: automatic walk cycle (legs ±30°·sin, arms opposite) blended in, speed-proportional.
- Look-at: head part turns toward the nearest viewer within look-range (global, region thread), clamped ±70° yaw, ±40° pitch.
- Nameplate holograms / triggers / particles keep working (model eye height = 1.62 × scale).
